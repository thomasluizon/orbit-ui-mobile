# apps/desktop

Tauri 2 shell for macOS and Windows. The webview loads the deployed web app; this workspace owns no screens, web build or API client. Root conventions apply.

- Keep the Rust entry point minimal. Do not add native commands or plugins without their carrying ticket and origin-scoped capabilities.
- Staging is the default build. Production uses `src-tauri/tauri.production.conf.json`; keep identifiers and webview storage separate.
- Email sign-in, habit logging and Astra use the web origin's existing BFF and httpOnly cookies. The native Google handoff transfers BFF cookie headers directly into the webview cookie store. Never persist tokens in native storage, JavaScript storage or configuration, or expose them to page JavaScript.
- Keep Tauri crates and the npm CLI pinned exactly. Confirm configuration and CLI interfaces against the installed sources before changing them.
- Keep single-instance first in plugin registration so secondary launches forward links before restoring the existing window. macOS Dock reopen, tray Open and accepted deep links share the same show, unminimize and focus path.
- Closing the main window hides it and keeps its webview alive. Quit saves geometry and exits. Never persist window visibility, which could hide the next launch.
- Native menus follow the system locale at launch. Keep every label in both `locales/en.json` and `locales/pt-BR.json`. The palette script drives the existing web keyboard hook and must retain its modal focus guard.
- Launch at login is an opt-in native menu setting. Use the official autostart plugin with the environment identifier as its registration name. Never enable it during setup.
- Lifecycle plugins receive no JavaScript permissions. Remote capabilities cover session completion and native push registration on the exact environment origin and main window. App deep links accept only known routes without queries or fragments; auth callbacks retain their separate state and proof checks.
- Native reminders use the signed bundle's APNs entitlement or the configured WNS service principal Object ID. Missing configuration stays inert. Keep the device UUID stable, persist attempted registrations before API writes, and revoke confirmed and uncertain endpoints before clearing the BFF session. Windows stays unpackaged with its push process and COM apartment alive after window close. Render APNs once through UserNotifications and WNS raw content through AppNotifications.
- Updater, dialog and local notification plugins receive no JavaScript permissions. Check at launch, on main-window focus and every minute. Download and verify shell updates in the background, then show the native restart dialog once per version while the main window is visible. Hidden windows defer the dialog until shown. Restart now uses the web settle and account-bound Astra checkpoint checks before installation. Later or dismissal installs the verified package natively on Quit with no web hand-off or relaunch. Only a running installation delays exit; repeated Quit waits for it, and a failed installation retains the package and exits. Closing the window only hides it. The origin-scoped application update command coordinates the existing notice slot and native menus. Retain failed packages for explicit retry and restore the same-origin route after shell relaunch.
- Update endpoints and signing keys belong to the environment. Require TLS and version-bound signatures; never allow downgrades. Empty source public keys disable updates in development builds; release builds must supply a real public key through a config overlay.
- `npm run test -w @orbit/desktop` validates configuration against the installed CLI schema. `cargo test --locked` in `src-tauri` tests the generated native context without opening a window.
- Native compilation and packaging run in `desktop-build.yml`. The root Turbo build excludes native packaging so web and Android jobs do not require desktop SDKs.
- `release.yml` calls `desktop-build.yml` and `desktop-release.yml` with its exact selected SHA before deploying web. The reusable publisher compares shell inputs with the channel manifest's immutable version tag and publishes only changed inputs; explicit manual shell releases remain available. Use GitHub environments `desktop-staging` and `desktop-production` for separate updater keys. `--no-sign` also skips updater signing in the pinned CLI, so sign the collected packages explicitly with `tauri signer sign --app-version` afterward. Verify every signature against the embedded public key before publishing; advance the stable channel manifest last.
