screen  The step up challenge guards the two operations that can outlive a session. The eyebrow names the operation being confirmed, because a code screen that does not name what it authorises looks like a phishing page. There is no plan axis: the screen has no gate.

operations  There are two operations. Delete account is the live one. API keys is the planned one. Billing is not a step up operation, because it hands off to the Stripe customer portal, which authenticates the person itself.

hand off  This screen is the hand off. The conversation sends the person here and never asks for a code where the person stands. The screen is reached from Perfil only. The note at the end says that Orbit never asks for a code in a conversation.

before  The step before this one belongs to Perfil: a plain confirmation with its own warning card. This screen is the SECOND gate. The way back from here is the cancel link, which routes to Perfil.

success  The right code does NOT delete. It deactivates the account with a date, and the screen shows the date that the server returns. The deactivated state says that the account comes back whole if the person signs in before that date. Its one action signs the person out and lands on Entrar. The Pro variant states the end date of the plan on its own line.

constraints  Four numbers are drawn, not described: a challenge lasts 10 minutes, resend has a 60 second cooldown, there are 3 attempts, and the attempt window is 15 minutes. The challenge ARRIVES with the cooldown already running, because the send opens this screen. The attempts are counted per email address over the window, so a new challenge does not restore them.

failures  There are three failures, and each offers a different action. A wrong code leaves the field usable and states the attempts left over their window, because retyping is the fix. An expired challenge disables the field and offers a new challenge, because retyping a dead code cannot work. Exhausted attempts offer NO action that would be refused. The notice states the lock, says that a new code does not restore the attempts, and keeps only a quiet route back to Perfil.

attempts  The count is attempts remaining, not attempts used. It is never phrased as a warning.

accent  One filled action per state where a way forward exists: confirm while the challenge is live, a new challenge when it expired, sign out on the deactivated states. Exhausted has NO filled action. Resend is a quiet ghost, so the two paths are never confusable.

shell  There is no shell. A challenge takes over, so there is no tab bar to wander off through, and cancel is an explicit link. At wide width the same column sits centred in a panel.
