screen  Entrar gets a person in and nothing else: the mark, one line, the field, and the two ways in. No feature list, no screenshots, no plan, no testimonial. Two exceptions: the legal line, because this is the only place a person agrees to anything, and the habit count on the arrival from onboarding.

identity  the sign in is the sign up: the first correct code creates the account. That is why no account not found state exists on this screen, and why no one can learn from it whether an address has an account.

referral  a referral cookie set by a shared Wrapped link draws a banner above everything. It promises nothing to a person who already has an account, because the referral applies only to a new account.

arrivals  two more ways in than the plain visit. From onboarding: the heading becomes the save your plan title and a line counts the habits waiting on the device, in singular and plural forms, with data-mock. From a link: an address with an email and a valid code opens the code step with the six digits filled and completes the ordinary verification once connectivity, bot protection and the session permit it.

states  two steps only, email and code. No plan axis: there is no gate before a person is in.

typing  the sixth digit submits on its own, deduped, and the button stays. A confirmation that a code went out shows after the send and after a resend. A returning deleted account is told its account is back, with one action into Hoje.

failures  the code has three failures, drawn as three screens, because they need different copy and actions. A wrong code leaves the field usable. An expired code says the code lasts 5 minutes and offers a resend and not a retype. A lock after 3 attempts says how long the wait is and offers no verify and no resend, since those fail for 15 minutes. The change of address stays, because the lock is per email address. A 429, every 5xx and a network error are one send failed shape, with the typed address kept. A Google failure is a line under the button. The inline message is the only message, with no duplicate toast.

resend  two states. While the window is closed it is a mono countdown and no control. When it opens it becomes a quiet ghost action. The countdown is a fixture and not a live timer.

loading  neither step blanks. Sending keeps the email step on screen with the action loading, and verifying keeps the six digits visible.

errors  every error sits next to its field, in both locales, and states the fix: the email error carries the shape of a complete address. No bare code, no status number, no shame.

offline  drawn on both steps: a neutral notice naming the circumstance, the primary disabled with its reason beside it, and the Google path disabled too. It is a boundary, so no status colour appears.

google  one ghost action under a divider, equal in width to the primary and lower in weight, with no Google logo, because the system holds no third party brand asset.

legal  one sentence under the Google action with links to the terms and the privacy policy. Both land on Sobre, since neither document is drawn here.

accent  one filled action per step, the step's own forward action, at both widths. Current position is the focused field ring and the active digit cell. Everything else is quiet.

open  whether a person returning to a still valid code should see the digits they already typed, and whether the referred banner should persist onto the code step.
