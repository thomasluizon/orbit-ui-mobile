screen  Offline is not one screen. The drawing shows two behaviours. On mobile, the app queues the change and the row moves at once. On the web, a few surfaces refuse in place and say why. There is no plan axis: offline is not a plan boundary.

mobile  The row changes at once and has no pending mark. A mark would tell the person that the log did not count, but it did. Three global toasts show the queue instead. They count changes, never logs.

toasts  Toast has four kinds: neutral, working, done and lost. Queued and failed retrying use the neutral kind. Failed retrying has no action, because the queue retries by itself. Synced is the only toast that leaves on its own.

dropped  Dropped is the only state that loses data. The toast names the lost change and says that the rest of the queue landed. It offers one action: do it again. It never leaves on its own.

web  The web has no queue. Each surface that needs the network refuses in place, next to its control. The creation refusal is WEB ONLY, because on mobile creation works offline like any other change.

accent  The redo action is the one filled action in the dropped state. The other toasts have no action and no accent.
