screen  Creation describes a habit in as few decisions as possible. One input, one sentence stating what Orbit understood, two tappable corrections, and one disclosure for everything else. It is not a schedule form: there is no type picker, none of the four internal type names renders in either locale, and there is no colour swatch row, because colour as data is gone.

states  empty, typed, resolved, unresolved, from the conversation, proposed unasked, details open, reading the phrase, at the daily limit, the same set Hoje’s create states reach. A plan axis sits beside the state, free or Pro, defaulting to free, and it moves exactly one gate on this screen, the slip alert inside the disclosure. Reached by using the screen rather than the axis: the ask runs the reading beat live and settles on Astra’s proposal, the emoji picker opens from the well, the disclosure opens from its row, and the templates and goal sheets open from theirs. The empty state is what the create action opens: nothing is proposed before there is something to propose.

input  the words the parser consumed are marked inside the field, so it is visible what was read and what was ignored. The marking is a background and a baseline rule only, never padding, so the marked text keeps the same metrics as the plain text. The field is a highlighted mirror under a transparent textarea sharing one metric declaration, which is what keeps the two aligned to the pixel.

parser  reading the sentence happens on the device first. The local read is regex over weekdays, times, counts and the daily phrases: it runs on every keystroke, calls nothing and costs nothing, which is what makes a live preview compatible with a five message day. Weekdays beat a count, and a count beats a bare daily phrase. A time is read only with a separator or after the word for at, so the 3 in three times a week is never mistaken for an hour. Astra is the fallback, called only when the local read resolves nothing and the person asks for it, and what it can return is bounded by the suggestion contract: an emoji, a cadence, fixed weekdays, a flexible target, a time, and one breakdown, either sub habits or a checklist and never both. Neither path guesses silently: when nothing resolves the screen says so and offers the two controls and the ask.

proposed  the treatment marks who read the sentence. A value the device read is just resolved and renders as typed, because the marked words in the field already show what was read. A value Astra read wears the proposed state, fg-3 inside a dashed hairline, and it never takes the accent. The first tap on a day pill, the stepper or the emoji picker resolves the whole block to normal, because at that point the person owns the value. Astra proposing unasked is the same treatment with every value proposed and a line naming that nothing has been created yet.

emoji  the 46px well beside the understood sentence IS the emoji control (habit-form-fields.tsx:242 renders HabitEmojiSelector): tapping it opens a picker with a search that clears, the eleven category chips from habit-emoji-options.ts, and a grid of choices. With no emoji chosen and none read from the sentence the well shows a plus rather than a derived initial, because there it is an empty control and not a label. An emoji Astra proposed wears the block’s proposed state until it is touched.

disclosure  ONE disclosure, closed by default, holding creation’s ten sections in this order: exact time as a TimeField with the any-time hint; reminders, which are two things, offset chips over the ten shipping presets plus a custom number and unit when a due time exists, with the LAST offset locked and its reason beside it because reminders on with nothing set is a lie, and absolute clock times when none, each added through a small form whose add waits for a time, at most 5, with both refusals from validateScheduledReminders said in words, a timed habit nesting its clock times under the same switch; checklist items as real inputs that retype in place, each duplicable, removable and draggable, up to 50 with the cap stated where it bites, and the person’s own templates, load one, save the current items under a name (absent while the list is empty), delete one through ListRow’s real per-row action; sub habits up to 20; the bad habit toggle with its line; the slip alert, plan gated; tags up to 5 as plain word pills with no colour dot, since colour as data is dead; goal linking, ungated; end date; description. Below the disclosure the immutable start date and its reason, then the create action. Colour swatches stay deleted.

plan  free is the default because it is the account most people have and the harder case to get right. The slip alert on free is a row carrying the Pro badge that ROUTES to the upgrade, never a disabled control and never a silent tap; on Pro it is the real switch with its shield glyph, its label and its description, and it turns on and off. The goal link stays ungated on both sides: D70 moved goals out of the paywall, and a gate a decision removed does not come back. Every gated tap leaves this document for Orbit Pro through one route. The daily ceiling is a different kind of boundary, an allowance and not a plan: it quiets the one ask with the reason stated in the notice beside it.

start  the form states an immutable start date and the reason it cannot move. It does not show a next due date: that value changes every time the schedule advances, so a fixed label over it is a structural defect rather than a wording problem, and it is not drawn here at all.

limit  creating a habit spends nothing from the daily Astra allowance. The live read is local. The one path that spends a message is the fallback ask, through SuggestHabitSetupCommand.cs:35, so the ceiling stops that one action and nothing else. The notice states the allowance, the ask stands beside it disabled, and the pills, the stepper, the details and the create action all stay live, so a habit can still be created with no model call at all.

The field is 92 tall with 16 of padding on every side: the microphone and its 60px end reserve are gone, because the app has no voice control on this form. use-speech-to-text.ts is imported by the chat composer, the copilot rail and the composer hook, and by nothing under components/habits, so voice stays where it lives, in the shell composer.
