# Operations: workers, CI, merges, releases, consoles and devices

**At a glance:** the operating facts an orchestrator needs when it launches a worker, waits on CI,
merges, releases, changes infrastructure, or drives a browser, a console or a device. Read the
section for the activity you start. `orchestrate/SKILL.md`, `release/SKILL.md`,
`android-release/SKILL.md` and `CLAUDE.md` own the procedures; this file holds the facts they do not.
Hermetic layout facts live in `TESTING.md` `### Hermetic layout harness facts`.

## Workers and launches

- Start every `tools/launch-worker.mjs`, `tools/wait-ci.mjs`, `tools/wait-release.mjs`, `tools/wait-file.mjs` and local check as a Bash background task with `timeout` 7200000, with no pipe and no trailing `&`. The default background limit is 30 minutes and kills the launcher and its worker mid-run; a pipe ends the process early and the wake notification never arrives.
- Gate each worker launch in the same background command that starts it, under the shared launch lock, with `LOAD_MAX=60 SPACING=45` on the one-minute load figure. A load check in one call and a launch in another is not a gated launch. Never pipe a launcher into `head`: its final line dies on EPIPE.
- A gated launch script that is killed while it holds its lock directory leaves the lock behind; the gate records its owner pid and reclaims a dead owner's lock. Never run a launcher inside a foreground command: a call that outlives its timeout moves to a 30-minute background task, which kills the worker at that limit.
- A worker order for `orbit-api` cannot file tickets (the ticket tools live in this repository); the orchestrator files what a worker reports.
- Worker logs live in `orbit-workers` under `os.tmpdir()`, which a reboot empties. A worker killed by a reboot leaves commits but no report: relaunch it with a continuation order that names its commits, never write its report by hand.
- An order composed before the main checkout fast-forwards lacks the newer composer text. Recompose an order after every fast-forward before you launch it.
- `tools/create-worktree.mjs` takes a numeric `--issue` (no `#`) and an absolute `--repo path:<p>` (`path:.` fails with `repo_not_found`). Orca names the branch `thomasluizon/<name>`: rename it to `fix/` or `chore/` before you compose the order. Create each worktree in its own call; several calls in one shell loop fail with "orca worktree create failed with exit 1".
- Orca runs `npm install` in every new worktree; an `npm ci` started at the same time fails `ENOTEMPTY` (exit 190). Wait until no `npm install` or `npm ci` process runs in the worktree (`pgrep -f "npm install"`), then run `npm ci`. A worktree without `node_modules` fails the pre-commit `i18n-usage` hook, and the hooks refuse a symlinked `node_modules`.
- A worker log repeats the order's `NEEDS_DECISION: <one question ...>` template text. Only a final `NEEDS_DECISION:` line that names a concrete question is a decision request.
- Claude Code expands `@/path` mentions in a `-p` prompt into file attachments before inference, even with an empty tool list. Every headless `claude` call on untrusted text (a ticket body, a review dossier) runs with `CLAUDE_CODE_DISABLE_ATTACHMENTS=1`.

## CI and checks

- Read test results by exit code, never by summary text: with the locale unset, the summary prints in Portuguese.
- A body edit re-runs Guards, and its concurrency group cancels the push's run. Read `gh run list --commit <sha>` before you call a check red.
- A pull request that conflicts with its base runs no CI. "Settled with no failing checks" is not green until the rollup shows the workflow checks; merge the base forward first.
- A rerun of a `pull_request` workflow reuses the merge commit of its first trigger, so a red caused by an older base never clears on a rerun. Settle it with the local merge-result check, which counts when the pull request shares no file with the base change, or with a base merge.
- A pull request event runs the workflows of its test merge commit, which GitHub recomputes lazily. After the base changes its workflows or required checks, read `gh api repos/<owner>/<repo>/pulls/<n>` (it recomputes `merge_commit_sha`), confirm the merge commit's parent is the current base, then edit the body to run `PR Metadata`, or close and reopen at the same head to run every workflow.
- A `parity:exempt` label does not change a run created before the label. Trigger a fresh pull request event after you apply it.
- GitHub Pro permits 40 concurrent hosted jobs. CI minutes per push are a shared budget: avoid duplicate source pushes and unnecessary base merges.
- `PR Tests` (Unit Tests, then SonarCloud) takes 35 to 50 minutes, so a `wait-ci.mjs` waiter started at a push can end on its 45-minute `CEILING` first: read the checks, then restart it. `wait-ci.mjs` ends with `HEAD_MOVED` when any of its pull requests gets a new push and with `READ_ERROR` on a transient read: restart it, with no more than three waiters. Its settled line lists checks from cancelled duplicate runs as `failingChecks`; read `gh pr checks <n>` at the head first.
- Use `npx turbo run type-check --force` from the repository root when cache freshness matters.
- Run the `orbit-api` suite with `LANG` unset and with `LC_ALL=en_US.UTF-8` to catch host-culture formatting. The `orbit-api` `Mutation (domain)` job is not required and can reach its timeout on a large diff: rerun it once and record the timeout on the pull request.
- `GitGuardian Security Checks` is required on `main` in `orbit-api` and `orbit-landing-page`; its suite can sit queued in the vendor backlog, and only waiting clears it. On `orbit-api`, the `CodeQL` results check is not required (the `Analyze` jobs are); dismiss a verified false positive with a written reason under 280 characters and rerun CodeQL.
- SonarCloud's gate (new-code coverage 80 percent or more, reliability A) is part of green checks. "Coverage on New Code" combines line and condition coverage from the `unit-test-coverage` artifact (`gh run download <run> -n unit-test-coverage`): a change inside a JSX attribute or a style object adds no coverable line, and an uncovered new condition (`BRDA` with 0 hits) lowers the figure. Rule `css:S4662` flags any at-rule missing from its ignore list, so `@slot` inside a `@custom-variant` body is a MAJOR bug there; a Tailwind `@plugin` carries such a variant instead.
- The GitHub GraphQL budget is 5,000 points an hour, shared by every tool, worker and agent on the account. Pause between calls in a loop over tickets or worktrees and stop on the first rate-limit error. `create-ticket.mjs`, `complete-ticket.mjs` and the board status helpers scan the whole project on each call: file tickets in small groups and never loop `--repair-status`. `gh issue list --search` spends the separate search limit. REST keeps working while GraphQL is exhausted, and the REST `rate_limit` view can show a stale GraphQL figure: probe with `gh api graphql -f query='query{rateLimit{remaining resetAt}}'`.

## Review and merge

- Read every worker diff before it counts: check each colour, size and shape it adds against `DESIGN.md`, and look for gate edits (D95).
- A fix that touches a reusable pattern (a focus rule, a toast, a sheet) is checked on every surface that uses the pattern before it merges.
- Base-merge a pull request only when it conflicts or its checks need a fix that landed on the base; a head that shares no file with the newer base merges at its approved head. Every base merge restarts about 180 job-minutes of `orbit-ui-mobile` CI and a fresh review.
- Several approved pull requests may merge on one combined local merge-result check: a scratch worktree at the base with every head merged, then `npm ci`, `npx turbo run type-check --force`, `node tools/check-i18n-usage.mjs`, `node tools/surface-manifest.mjs --check`, `node tools/check-sonar-paths.mjs`, the three Vitest suites, the web build and, when the change touches `apps/web`, the hermetic layout project, all by exit code. Two pull requests that are each green alone can turn a layout spec red together.
- Merging one approved pull request can turn a sibling that shares files into a conflict. Before you merge, run `git merge-tree --write-tree --name-only` of each open head against the post-merge tree, and merge first the pull request whose files the others build on. Two pull requests that edit the same `CLAUDE.md` registry row or drawing conflict: merge one, then base-merge the other.
- Pullfrog readiness reads the last review of the exact head and the newest `pullfrog-approval` check; review body findings count with zero unresolved threads. Pullfrog can approve a head whose required checks are red, so readiness reads every check at the exact head.
- Pullfrog runs as several `workflow_dispatch` runs of `pullfrog.yml` on `main`. A pushed base-merge head can wait in that queue or get no review; `--re-review` fixes that. `list-bot-threads.mjs --re-review` refuses `--wait-seconds 0`: to ask for a review without a waiter, post a plain `@pullfrog review` comment only on a head whose CI passed, and read the verdict later with `--wait-seconds 0 --no-request`.
- Pullfrog reviews only on request, through the console settings `review.mode` `none` and `review.re-review` `false`. `node tools/list-bot-threads.mjs --pr <n> --repo <key>` asks only after every check of the head, except Pullfrog's own, passed, and only once for each head. It reports `CI_FAILING` or `CI_PENDING` and posts nothing until then.
- A `wait-ci.mjs --require-check pullfrog-approval` waiter keeps a wake source alive until Pullfrog publishes its approval on a green head; a plain waiter ignores the protected `pullfrog-approval` check and exits as soon as the other checks settle, which is the signal to ask for the review. When the former ends with `CEILING` and the check is unpublished, nobody asked for that head's review: run `list-bot-threads.mjs` without `--no-request`.
- The Pullfrog console model stays "Custom (set in workflow)" in all three repositories: a stored console model overrides the workflow's `model` input. The console then shows the Smart tab with no provider. A raw Pullfrog model specifier gets no effort rung and no subagent override, so `reviewfrog` inherits the main model.
- A worker report does not always use the `## Test evidence`, `## Assumptions`, `## Manual steps` and one-line-per-lane `## Review harness` shape that `merge-review-batch-body.mjs` reads, and its log prints the final message twice. Rebuild the report from the last copy. A pull request with no animation change writes the motion lane as `not applicable: no changed animation`. After the merge, grep the body for superseded design claims.
- Workers often forget `parity:exempt` on a one-sided change; Cross-Platform Parity fails until the label and a `## Parity` line are added.
- Link tickets in `orbit-api` and `orbit-landing-page` bodies as `thomasluizon/orbit-tickets#N`; a bare `#N` names that repository's issues. A `Closes thomasluizon/orbit-tickets#N` line there closes the ticket on merge, so write `Refs` when the ticket still has work after the merge. Strip a `Closes` or `Resolves` line from a worker's body in this repository.
- The board's "Item closed" workflow is off, so a ticket closed by a merge keeps its board Status and `teardown-worktree.mjs` refuses its worktree: run `node tools/complete-ticket.mjs --issue <#N> --repair-status` on it.
- A read-only search subagent's verdict about a branch is a lead. Confirm it with `git show <branch>:<path>` or `git diff <base>...<branch>`.
- A closed allowlist only shrinks: when a fix removes suppressions, lower `orbit-api` `tools/suppression-allowlist.json` to the observed count. `orbit-api` does not commit its architecture map; run `node tools/arch-map.mjs` there first.
- Record a deleted surface ID with its decision in `tools/redesign-groups.json` when you regenerate the surface manifest.
- A GitGuardian finding is fixed at the source. When an older commit still carries it, republish the approved tree as one commit on a new branch from `main` and close the old pull request; never force push. Do the same for a pushed branch that carries an attribution line.

## Releases and infrastructure

- Never run a production web release and a production API release at the same time: sign-in, deletion and API key codes live in a per-instance memory cache until the `#315` fix lands. Never run a staging web release while a production web release runs. An API release with a migration takes a fresh Render export first. Every destructive operation gets its own current backup and drain proof.

## Secrets and accounts

The permission classifier blocks credential materialization unconditionally. A secret that exists only in a dashboard with no API is not used.

## Browser and consoles

- Do console and dashboard steps yourself through `claude-in-chrome` (Play Console, App Store Connect, Cloudflare, Render, Google Cloud, Azure, SonarCloud): a manual step is the run's work unless it needs the owner's password, 2FA, payment or legal identity choice. Fill every field you may, take a fresh screenshot before any step you hand over, and hand over only the blocked field in one line. A browser task includes its own save and publish clicks. A Play Data safety change waits until the build it describes is live.
- A sleep run does its visible Chrome work whether or not the owner uses the Mac.
- When an MCP reaches the wrong account, use `claude-in-chrome` instead.
- Chrome work, the run's and every subagent's, happens in one tab of the Chrome window that is already open: never a new window, a popup, `window.open` or `resize_window`. Measure at the window's current width and record it. Page reads and browser steps go through `claude-in-chrome`, never `orca computer` keystrokes; when the session has no tab group, create one, use its one tab and close it after. `orca computer get-app-state --app com.google.Chrome --restore-window --no-screenshot --json` only brings a hidden Chrome window forward. The orchestrating session does in-app deletions itself, because the classifier can refuse a subagent's click.
- The exception: the extension cannot act on `accounts.google.com`, so Google's account chooser and consent pages are driven with `orca computer`. Take a fresh screenshot right before every coordinate click there (a debugging banner shifts every row by about 56 points), and prefer element-index clicks.
- `claude-in-chrome` can be connected to a remote Windows Chrome: run `list_connected_browsers` and select the local macOS one first. A window that will not resize and an `outerWidth` of 0 mean the wrong browser. The local Chrome's smallest viewport is about 600 wide (the phone layout; the wide shell starts at 1024); stay within the screen (desktop 1352 by 820, phone 600 by 820). Read `innerWidth` and `innerHeight` after every resize. Staging refuses framing. A navigation can leave the tab on its new-tab page: repeat it.
- The automation window often reports `document.visibilityState` hidden. Then animations stall (two route layers, a sheet that keeps focus or ignores Escape, a click that looks dropped), page timers throttle past the 45-second CDP limit (wait with the browser tool's own wait), and Play Console refuses some saves (users and permissions, a new subscription base plan) and wizard sections do not expand. Run `document.getAnimations().forEach((a) => a.finish())` and re-check, or finish in a visible window. Only the window's active tab is visible. When the screen is locked (`ioreg -n Root -d1 -a` reports `CGSSessionScreenIsLocked`), console steps and sweeps wait.
- Every rendered sweep scrolls each screen to its end at both widths and checks that the last element clears the pinned chrome (bottom clearance is the shell's job), and includes foldable widths (about 480, 840 and 1100). A wide load server-renders the compact shell first: screenshot a desktop page only after the sidebar shows. A cold `/calendar?mode=review` opens its sheet only after the data arrives. A sweep may create, log and delete test habits and send Astra messages in the owner's staging account, never in production.

## Machine and shell

- Keep the Mac awake while a session runs; a closed lid still sleeps it. The keep-awake hook holds `caffeinate -dims`: without `-d` the display sleeps and the screen locks at once, which hides Chrome.
- Never configure anything that needs administrator rights on the owner's Mac. Never build the desktop app locally; install it only on the owner's explicit order.
- A reboot empties the system temporary directory: session scratchpads, scratch merge-check worktrees under them and `orbit-workers` vanish. Leave registrations to `git worktree prune`.
- The orchestrator guardrail refuses a redirect whose target holds an expansion (`> $DIR/file`, `> $(...)`): name a literal path or run a helper script.
- `ls` is aliased to eza, which rejects `-t` with a path: scripts use `command ls`. A pipe whose producer fails can leave `awk` reading standard input. In zsh, `"$SHA:path"` applies a modifier: write `"${SHA}:path"`.
- A leftover `next-server` on port 3000 serves a stale build: check `lsof -nP -iTCP:3000 -sTCP:LISTEN` before a local smoke run.
- When the owner asks about the terminal view, answer with Ctrl+L or a pane resize and keep working.
- Merging a change to `.claude/settings.json` and fast-forwarding the main checkout activates the new hooks in the running session.
- Read every decision log time from `date -u` at the moment of writing; never write a time ahead of the clock.
